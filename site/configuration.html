Configuration

Two committed files control vci: vci.toml sets policy, and .vci/allowed_signers says whose attestations count.

CI reads both from the base commit, the tip of the branch a pull request merges into. A change to either file in a pull request has no effect on that pull request; it takes effect once merged. If either file is missing or unreadable at the base commit, everything runs. See trust comes from the base branch.

vci.toml

This is a complete file for one Vitest project. vci init writes a longer, commented version of it.

project = "."          # project dir, relative to the repo root
adapter = "vitest"     # or "pytest", "go", "cargo", "rails"

[policy]
# Nothing is skipped on these refs: every merge gets a full run.
no_skip_refs = ["refs/heads/main", "refs/tags/**"]
# ...except what CI's own key attested (see GitHub Actions).
# no_skip_refs_except = ["github-actions"]

[env]
mode = "strict"                # undeclared variables are removed
global = ["NODE_ENV", "TZ"]    # hashed into every unit's inputs
pass_through = []              # visible, never hashed: secrets go here

Every key you leave out takes its default, listed below. Unknown keys are errors.

KeyDefaultMeaning
project"."The project directory (where the test runner runs), relative to the repository root.
adapter"vitest"The test runner: "vitest", "pytest", "go", "cargo" or "rails".
runnerdetectedRails only: "minitest" or "rspec". See RSpec.

The rest of the file is four tables, explained in order below: [policy], [env], [[inputs]] and, for a repository with several projects, [[projects]].

[policy]

When an attestation is good enough, and where nothing is skipped.

KeyDefaultMeaning
platform"any"Which OS and architecture may satisfy CI. "any" accepts an attestation from another platform, "same-os" requires the same OS, "exact" requires the same OS and architecture.
libraries"exact"Rails and pytest: how native libraries and the interpreter's library versions are compared. "exact" matches a library opened through FFI (libvips) by file name and hash, and compares the SQLite, libyaml, time zone data and OpenSSL versions. "any" matches the library by name (libvips.42.dylib on macOS, libvips.so.42 on Linux), which must still be loaded in CI, and ignores those versions. See macOS to Linux.
max_ttl"30d"Longest accepted attestation lifetime. vci run --ttl sets the lifetime of a new attestation (14 days unless you say otherwise).
allow_dirtytrueAccept attestations made from a working tree with uncommitted changes. Inputs are hashed by content, not by commit.
no_skip_refs[]Refs on which nothing is skipped, except what no_skip_refs_except allows. vci init writes ["refs/heads/main", "refs/tags/**"]. Keep your default branch here: that full run is the backstop against a false claim.
no_skip_refs_except[]allowed_signers principals whose attestations may still skip on a no_skip_refs ref, such as ["github-actions"] for CI's own key (see attesting in CI). There, every other signer's attestation fails the signer check. Empty: those refs run everything. List no developer or agent here.
never_skip[]Project-relative globs of test files that always run. Use it for tests whose inputs no collector can see.
go_allow_netfalseGo: attest packages whose test links package net. See Go.

Removed: rails_allow_db was removed in 1.4.0, because vci no longer manages the Rails test database: a database server configured for the test environment needs no policy (see Rails). The key is a deprecated no-op kept for compatibility. A vci.toml that still sets it, at the top level or in a project, parses, so a base commit that has it does not make every test run; it has no effect, and vci run and vci plan print one warning. Remove it.

Platform overrides

Tighten the platform rule for some files and leave the rest on "any". An entry sets platform, libraries, or both:

[[policy.platform_overrides]]
match = ["src/native/**"]   # project-relative globs
platform = "exact"

[[policy.platform_overrides]]
match = ["test/images/**"]
libraries = "exact"

Overrides only tighten: the strictest of [policy] and every matching entry applies.

macOS to Linux

Under platform = "any", a Rails file that loaded libvips (any file that boots an app with Active Storage and image_processing) still runs on a Linux runner: Homebrew's libvips is a different file from apt's. The same happens when the SQLite, libyaml or time zone data versions differ, or, for pytest, the interpreter's SQLite or OpenSSL. To skip those files across platforms:

[policy]
platform = "any"
libraries = "any"

Install libvips on the runner as well; under "any" it is matched by name, but it must still be loaded there. Everything else is still compared exactly: the Ruby or Python version, every gem or distribution in the lockfile, the inputs and the declared environment. By setting it you state that these libraries behave the same on both platforms for your tests. vci explain lists every difference the policy accepted.

[env]: environment variables

Environment variables can change a test's result, so vci controls which ones a test sees and hashes the ones that matter. In strict mode, the default, a test sees only the variables you list in [env], plus a few built-ins such as PATH. This holds both in vci run and in CI:

The design follows Turborepo's env, globalEnv and passThroughEnv, with one addition: vci also observes which variables each test actually reads.

[env]
mode = "strict"          # "strict" (default) | "loose"
# hashed into every test's inputs
global = ["NODE_ENV", "TZ", "CI_*", "!CI_JOB_*"]
# visible to tests, never hashed
pass_through = ["GITHUB_TOKEN", "AWS_*"]

[[env.files]]            # additions for matching test files
match = ["src/db/**/*.test.ts"]
env = ["DATABASE_URL"]
pass_through = ["PG*"]

Patterns are exact names, * wildcards, and a leading ! to exclude. Exclusions win. Matching is case-sensitive.

Strict and loose mode

Each variable falls in one of these groups:

VariableReaches the testHashed
Declared (global, per-file env)yesyes
Pass-through (pass_through)yesno
Built-in pass-through (PATH, HOME, USER, TMPDIR, LANG, CI, ...)yesonly if the test was observed reading it
Undeclared, strict modeno (removed)recorded as absent if read
Undeclared, loose modeyesyes, if the test was observed reading it

Strict mode removes undeclared variables in both vci run and vci ci, so local and CI runs see the same environment shape. To give your tests a variable, declare it in global and set the same value on both sides.

A test that reads CI, HOME or USER is never skipped on a runner when it was attested on a laptop. Those values differ by definition, and a variable a test reads is hashed.

NO_COLOR and FORCE_COLOR are removed in strict mode too. Add them to pass_through if you need them.

Secrets

vci never stores values, only their BLAKE3 hashes. But anyone who can read the attestations can brute-force the hash of a low-entropy value. Put secrets in pass_through, not in global. vci run warns when a declared name matches *TOKEN*, *SECRET*, *PASSWORD* or *KEY*.

Runner-specific variables

Each adapter adds the pass-through variables its toolchain needs (uv's UV_*, Go's GOPATH and GOCACHE, Cargo's CARGO_HOME, Bundler's BUNDLE_PATH, ...). It also hashes, whenever they are present, the ones that change behaviour (PYTHON*, GOFLAGS, RUSTFLAGS, RAILS_*, ...). The full table is in docs/ENV.md.

[[inputs]]: extra inputs

Declare files a unit depends on that vci cannot find on its own. Any adapter accepts this; the cargo adapter needs it for tests that read outside their package directory.

[[inputs]]
# unit ids (globs)
match = ["crates/b#test:*"]
# files, relative to the project dir (globs)
extra = ["testdata/**", "shared/config.json"]
  • A glob without wildcards names a file, a directory (walked), or a path that must stay absent.
  • With wildcards, every matching file is hashed and each directory walked is recorded as a listing, so a new matching file is noticed.

Several projects in one repository

Replace project and adapter with a list of [[projects]]. The top-level [policy] and [env] become shared defaults. A key in a project's own table replaces the top-level key for that project only:

[policy]
max_ttl = "30d"

[env]
global = ["NODE_ENV"]

[[projects]]
name = "web"           # unique: letters, digits, '.', '_', '-'
path = "web"
adapter = "vitest"

[[projects]]
name = "api"
path = "services/api"
adapter = "pytest"
[projects.policy]
platform = "same-os"
[projects.env]
global = ["TZ", "APP_*"]
  • Test ids stay repo-relative paths, so they are unambiguous across projects.
  • vci run, plan, ci and explain work across all projects.
  • vci run FILE only needs the toolchain of the project that file belongs to.
  • A project can also set its own runner, and its own inputs = [...], which replaces the top-level [[inputs]] list.

.vci/allowed_signers

The trust root: the keys whose attestations CI accepts. It uses OpenSSH's allowed_signers format, one line per person or agent:

alice@example.com namespaces="vci-attest" ssh-ed25519 AAAAC3Nza...
build-agent namespaces="vci-attest",valid-before="20270101" ssh-ed25519 AAAAC3Nza...
  • namespaces="vci-attest" limits the key to vci attestations.
  • valid-after and valid-before are honoured. Give agent keys an expiry.
  • cert-authority entries are rejected.
  • To revoke a signer, remove the line on the default branch. Attestations by that key stop being accepted at once.

.git-meta

Names the remote that attestations are exchanged with. vci init writes url: with your origin's URL; pass --meta-url URL to keep metadata in a separate repository.

CI should name the remote itself, as the action does with vci fetch --remote origin, so a pull request's .git-meta never chooses where attestations come from. See where attestations live.
