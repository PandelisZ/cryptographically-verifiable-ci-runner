Configuration

Two committed files control vci: vci.toml sets policy, and .vci/allowed_signers says whose attestations count.

CI reads both from the base commit. A change to either file in a pull request has no effect on that pull request. It takes effect once merged. If either file is missing or unreadable at the base commit, everything runs.

vci.toml

vci init writes a commented starting file. The full shape:

project = "."          # project dir, relative to the repo root
adapter = "vitest"     # or "pytest", "go", "cargo", "rails"

[policy]
platform = "any"       # "any" | "same-os" | "exact"
max_ttl = "30d"
allow_dirty = true
no_skip_refs = ["refs/heads/main", "refs/tags/**"]
never_skip = ["tests/test_attach_db.py"]
go_allow_net = false
rails_allow_db = false

[[policy.platform_overrides]]
match = ["src/native/**"]
platform = "exact"

[env]
mode = "strict"
global = ["NODE_ENV", "TZ"]
pass_through = ["GITHUB_TOKEN"]

[[env.files]]
match = ["src/db/**/*.test.ts"]
env = ["DATABASE_URL"]

[[inputs]]
match = ["crates/b#test:*"]
extra = ["testdata/**"]

Unknown keys are errors.

[policy]

KeyDefaultMeaning
platform"any"Which OS and architecture may satisfy CI. "any" accepts an attestation from another platform, "same-os" requires the same OS, "exact" requires the same OS and architecture.
max_ttl"30d"Longest accepted attestation lifetime. vci run --ttl sets the lifetime of a new attestation (14 days unless you say otherwise).
allow_dirtytrueAccept attestations made from a working tree with uncommitted changes. Inputs are hashed by content, not by commit.
no_skip_refs["refs/heads/main", "refs/tags/**"]Refs on which nothing is ever skipped. Keep your default branch here: that full run is the backstop against a false claim.
never_skip[]Project-relative globs of test files that always run. Use it for tests whose inputs no collector can see.
go_allow_netfalseGo: attest packages whose test links package net. See Go.
rails_allow_dbfalseRails: attest files whose test database is a server. See Rails.

Platform overrides

Tighten the platform rule for some files while leaving the rest on "any":

[[policy.platform_overrides]]
match = ["src/native/**"]   # project-relative globs
platform = "exact"

[env]: environment variables

Modeled on Turborepo's env, globalEnv and passThroughEnv, with one addition: vci also observes which variables each test actually reads.

[env]
mode = "strict"                                   # "strict" (default) | "loose"
global = ["NODE_ENV", "TZ", "CI_*", "!CI_JOB_*"]  # hashed into every test's inputs
pass_through = ["GITHUB_TOKEN", "AWS_*"]          # visible to tests, never hashed

[[env.files]]                                     # additions for matching test files
match = ["src/db/**/*.test.ts"]
env = ["DATABASE_URL"]
pass_through = ["PG*"]

Patterns are exact names, * wildcards, and a leading ! to exclude. Exclusions win. Matching is case-sensitive.

CategoryVisible to testsHashed
Declared (global, per-file env)yesyes
Pass-through (pass_through)yesno
Built-in pass-through (PATH, HOME, USER, TMPDIR, LANG, CI, ...)yesonly if the test was observed reading it
Undeclared, strict modeno (removed)recorded as absent if read
Undeclared, loose modeyesyes, if the test was observed reading it

Strict mode

In strict mode only declared and pass-through variables reach the test process. Everything else is removed, both in vci run and in vci ci, so local and CI runs see the same environment shape. To set a variable for your tests, declare it in global and set the same value on both sides.

A test that reads CI, HOME or TMPDIR is never skipped on a runner when it was attested on a laptop. Those values differ by definition, and a variable a test reads is hashed.

NO_COLOR and FORCE_COLOR are removed in strict mode too. Add them to pass_through if you need them.

Secrets

Values are never stored, only their BLAKE3 hashes. But the hash of a low-entropy value can be brute-forced by anyone who can read the attestations. Put secrets in pass_through, not in global. vci run warns when a declared name matches *TOKEN*, *SECRET*, *PASSWORD* or *KEY*.

Runner-specific variables

Each adapter adds pass-through variables its toolchain needs (uv's UV_*, Go's GOPATH and GOCACHE, Cargo's CARGO_HOME, Bundler's BUNDLE_PATH, ...), and hashes the ones that change behaviour whenever they are present (PYTHON*, GOFLAGS, RUSTFLAGS, RAILS_*, ...). The full table is in docs/ENV.md.

[[inputs]]: extra inputs

Declare files a unit depends on that vci cannot find on its own. Any adapter accepts this; the cargo adapter needs it for tests that read outside their package directory.

[[inputs]]
match = ["crates/b#test:*"]                     # unit ids (globs)
extra = ["testdata/**", "shared/config.json"]   # files, relative to the project dir (globs)

A glob without wildcards names a file, a directory (walked), or a path that must stay absent. With wildcards, every matching file is hashed and each directory walked is recorded as a listing, so a new matching file is noticed.

Several projects in one repository

Replace project and adapter with a list. [policy] and [env] become shared defaults, and each key in a project's own table replaces the top-level key for that project:

[policy]
max_ttl = "30d"

[env]
global = ["NODE_ENV"]

[[projects]]
name = "web"           # unique: letters, digits, '.', '_', '-'
path = "web"
adapter = "vitest"

[[projects]]
name = "api"
path = "services/api"
adapter = "pytest"
[projects.policy]
platform = "same-os"
[projects.env]
global = ["TZ", "APP_*"]

Test ids stay repo-relative paths, so they are unambiguous across projects. vci run, plan, ci and explain work across all projects, and vci run FILE only needs the toolchain of the project that file belongs to.

.vci/allowed_signers

The trust root, in OpenSSH's allowed_signers format. One line per person or agent:

alice@example.com namespaces="vci-attest" ssh-ed25519 AAAAC3Nza...
build-agent namespaces="vci-attest",valid-before="20270101" ssh-ed25519 AAAAC3Nza...
  • namespaces="vci-attest" limits the key to vci attestations.
  • valid-after and valid-before are honoured. Give agent keys an expiry.
  • cert-authority entries are rejected.
  • To revoke a signer, remove the line on the default branch. Attestations by that key stop being accepted at once.

.git-meta

Names the remote that attestations are exchanged with. vci init writes url: with your origin's URL; pass --meta-url URL to keep metadata in a separate repository. See where attestations live.
