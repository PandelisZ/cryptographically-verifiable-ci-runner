CLI reference

Eight commands. Three you use daily (run, plan, push), one runs in CI (ci), and one answers "why did this run?" (explain).

Commands

vci init

vci init [--key K] [--principal P] [--project DIR]
         [--adapter vitest|pytest|go|cargo|rails] [--no-install] [--meta-url URL]

Writes vci.toml, .vci/allowed_signers (adding key K) and .git-meta, configures the git-meta remote, and prints a CI snippet. For Vitest it also runs npm install for @vci/vitest unless you pass --no-install.

vci run

vci run [FILES…] [--key PATH] [--ttl 14d]

Runs tests with collection on, then signs and stores an attestation for every attestable unit. With no arguments it runs every unit. The exit code is the test runner's.

vci plan

vci plan [--base-ref R] [--format text|json|github]

Prints which units can be skipped and why the others run. Changes nothing.

SKIP tests/test_b.py  (attested by alice@example.com (SHA256:tsNeKgQt…))
RUN  tests/test_a.py  (no attestation)
1 to skip, 1 to run

vci ci

vci ci [--base-ref R] [--audit-log PATH]

Plans, runs the remainder, and writes a JSON audit log of every skip. Exits non-zero if any test fails.

vci explain

vci explain <test> [--base-ref R]

Shows every candidate attestation for one unit and the first check each failed, with expected and actual values.

vci push, vci fetch

vci push [--remote R]
vci fetch [--remote R]

Exchange attestations on refs/meta/main, like git meta push and git meta pull. R is a git-meta remote, or a git remote or URL to use as one. Default: the configured git-meta remote, else the url: in .git-meta, else origin. In CI, always pass --remote.

vci prune

vci prune [--dry-run]

Deletes expired attestations from the local store. vci push publishes the deletions.

vci verify

vci verify <envelope|-> [--allowed-signers F] [--base-ref R]

Verifies one DSSE envelope and prints its claims.

Signing key

vci looks for the key in this order:

  1. --key PATH
  2. $VCI_SIGNING_KEY
  3. git config user.signingkey, when gpg.format = ssh

A GPG signing key is never used. A .pub path works when the private half is in ssh-agent, hardware keys included.

Base ref

The base ref is the trust boundary: policy and allowed signers are read from it. vci picks it in this order:

  1. --base-ref R
  2. $VCI_BASE_REF
  3. origin/$GITHUB_BASE_REF
  4. the first that exists of origin/HEAD, origin/main, origin/master, main, master

If none resolves, everything runs. vci plan warns when the base commit is HEAD or contains it, because then trust comes from the commit under test.

Environment variables

VariableMeaning
VCI_SIGNING_KEYSigning key path, used when --key is not given
VCI_BASE_REFBase ref, used when --base-ref is not given
VCI_JOBSParallel pytest, go test or Rails processes in vci run (default: CPUs, up to 8)
VCI_JS_PLUGINPath of the @vci/vitest package (default: node_modules/@vci/vitest above the project)
VCI_PY_PLUGINThe py/pytest-plugin directory
VCI_RUBY_COLLECTORThe ruby/vci-collector directory
VCI_NODE, VCI_UV, VCI_GO, VCI_CARGO, VCI_RUBYWhich binary to use for each toolchain, instead of the one on PATH

Looking at attestations directly

Attestations are ordinary git-meta values, readable with the git meta CLI:

git meta get path:src/b.test.ts
git ls-remote origin refs/meta/main
