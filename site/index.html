cryptographically verifiable CI

Skip the tests someone already ran. With proof.

If a developer or an agent already ran a test against exactly the files it depends on, CI should not run it again. vci makes that safe with signed, per-test attestations.

Get started Add to GitHub Actions 
$ vci run src/b.test.ts
  ran, collected inputs, signed, stored
$ vci push

# later, in CI
$ vci plan --base-ref origin/main
SKIP src/b.test.ts  (attested by alice@example.com)
RUN  src/a.test.ts  (no attestation)
RUN  src/c.test.ts  (inputs changed)
1 to skip, 2 to run

How it works

Three steps. The default verdict is always RUN: any error or doubt means the test runs.

1 · attest

Run and sign locally

vci run runs your tests with a collector that records every file, directory listing, missing-file probe, package version and env var each test used, then signs that record with your SSH key.

2 · share

Push through git

Attestations travel as git-meta metadata on refs/meta/main. No server, no database: vci push and vci fetch are git push and fetch.

3 · verify

CI re-checks everything

vci plan verifies the signature against the base commit's trusted signers, re-hashes every recorded input from its own checkout, and skips only on an exact match.

Works with your test runner

One repository can mix several. Each has its own unit of skipping.

vitest

Vitest

Per test file. Vitest 3.2 to 5, Node 22.15+.

 pytest

pytest

Per test file. pytest 9 on CPython 3.11 to 3.14, through uv.

 go

Go

Per package. Go modules, Go 1.26.

 cargo

Rust

Per cargo test target. Inputs decided conservatively.

 rails

Rails

Per Minitest or RSpec file. Rails 8, Ruby 3.4, fresh SQLite database per file.

What you can rely on

Fail open

A missing, expired, tampered or unreadable attestation only ever makes a test run. Nothing in the store is trusted on its own.

Trust comes from the base branch

Allowed signers and policy are read from the base commit, so a pull request cannot add its own key or loosen the rules.

Observed inputs, not guesses

Collectors record what each test really read at run time, including files that were probed and found missing.

Laptop to runner

An attestation made on macOS arm64 can be accepted on a Linux x86_64 runner when the toolchain and inputs match.

Know the limit. An attestation proves who made a claim, not that the test ran. A trusted signer can lie and a stolen key can sign. Keep the signer list short and keep full runs on your default branch. See the threat model.

Try it in five minutes

# install
curl -fsSL https://raw.githubusercontent.com/PandelisZ/cryptographically-verifiable-ci-runner/main/scripts/install.sh | sh

# in your repository
vci init --adapter pytest --key ~/.ssh/id_ed25519.pub
git add vci.toml .vci/allowed_signers .git-meta && git commit -m "Enable vci"

vci run tests/test_b.py --key ~/.ssh/id_ed25519
vci plan --base-ref origin/main
vci push
