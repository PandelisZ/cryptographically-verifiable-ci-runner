Test runners

vci has one adapter per test runner. Each decides what a "unit" is, how its inputs are found, and when it refuses to attest.

AdapterUnitHow inputs are found
vitesttest fileobserved at run time (module graph, file reads, env reads)
pytesttest fileobserved at run time (Python audit hooks, import system)
gopackageobserved at run time (a logger overlaid into the standard library) plus go list
cargotest targetconservative: every file of the package and its in-repo dependencies
railsMinitest fileobserved at run time (a collector wrapping Ruby's file, env and process entry points)

Common to every adapter. A unit is attested only when it passed, nothing it did was invisible to the collector, and every input is inside the repository. A unit with a skipped test is not attested (Rust's #[ignore] is the exception). An attestation vouches for the unit run on its own, in its own process.

Vitest

Needs Node 22.15+ and Vitest >=3.2 <6. The unit is a test file.

cd your-project
npm install --save-dev /path/to/vci/js/vitest-plugin   # or set VCI_JS_PLUGIN instead

vci init --key ~/.ssh/id_ed25519.pub --no-install
git add vci.toml .vci/allowed_signers .git-meta && git commit -m "Enable vci"

vci run src/b.test.ts --key ~/.ssh/id_ed25519
vci plan --base-ref origin/main
vci push

What is recorded

  • every module in the Vite graph and every module the worker evaluated, including computed import();
  • every file or directory read or stat'ed, and every failed lookup, so creating a file that was probed as absent invalidates the attestation;
  • external packages as name@version;
  • env vars: declared patterns, VITE_*, and anything the test read;
  • global inputs: package.json, lockfiles, .npmrc, the Vitest config, the tsconfig.json chain, vci.toml and the test's snapshot file.

What is refused

Child processes, network, worker_threads, fetch, enumerating process.env, snapshot writes, isolate: false, vm or browser pools, and typecheck mode.

Pin: Node major version and package-lock.json. Vitest and Vite versions must match.

pytest

Needs uv and pytest 9. The project must be a uv project with a committed uv.lock and a pytest config file in the project directory. The unit is a test file, run in its own process.

cd your-project
uv python install 3.14.4                  # a uv-managed build that also exists for the CI platform
echo 3.14.4 > .python-version             # pin the full version
export UV_PYTHON_PREFERENCE=only-managed  # never pick up the system Python
uv lock

vci init --adapter pytest --key ~/.ssh/id_ed25519.pub
git add vci.toml .vci/allowed_signers .git-meta uv.lock .python-version && git commit -m "Enable vci"

vci run tests/test_b.py --key ~/.ssh/id_ed25519
vci plan --base-ref origin/main
vci push

What is recorded

  • every module imported from the repository, including conftest.py files, and every path an import could have resolved to (so a new module that would shadow one is noticed);
  • every file opened or stat'ed, failed lookups and directory listings;
  • installed distributions as name@version, checked against uv.lock;
  • env vars read through os.environ, and always PYTEST_*, PYTHON* and TZ.

Any change to uv.lock runs everything.

What is refused

subprocess and friends, sockets and HTTP clients, ctypes.dlopen, xdist, reruns, unseeded random ordering, writing inside the repository, enumerating the environment (dict(os.environ)), and SQLite databases inside the repository.

Laptop to Linux runner

  • Use a uv-managed Python whose exact patch version uv also ships for Linux (check with uv python list --all-platforms). Homebrew's Python will not match.
  • Pin the same uv version locally and in astral-sh/setup-uv.
  • The full set of installed distributions must be equal. A dependency with a platform marker installs on one side only, so everything runs.
  • Delete .DS_Store and __pycache__ from directories your tests list. vci run warns about them.

Go

Needs a Go module and Go 1.26. The unit is a package: every directory with _test.go files. Test ids are package directories relative to the repository root.

cd your-module
vci init --adapter go --key ~/.ssh/id_ed25519.pub
git add vci.toml .vci/allowed_signers .git-meta && git commit -m "Enable vci"

vci run ./b --key ~/.ssh/id_ed25519   # default: every package with tests
vci plan --base-ref origin/main
vci push

What is recorded

  • compile-time inputs from go list: every file of each in-repo package in the import closure, its directory listing, go:embed targets, and files excluded by build constraints;
  • run-time inputs from a logger overlaid into the standard library for this build only: every file opened or stat'ed, every failed lookup, every env var looked up. This includes package initialisation and TestMain;
  • external modules as path@version, verified against go.sum.

What is refused

Starting a child process, package net anywhere in the import closure, cgo and syscall in non-standard packages, os.Environ, a skipped test, and using the local time zone with TZ unset.

Network waiver. Many test helpers import net/http without using it (testify's assert does). Set go_allow_net = true under [policy] to state that these tests do no network I/O. The waiver is recorded in the attestation and only accepted while the base commit's policy still sets it.

Laptop to Linux runner

  • Pin the exact Go version in actions/setup-go.
  • Declare CGO_ENABLED and TZ in [env] global, and set CGO_ENABLED=0 and TZ=UTC on both sides.
  • A package with platform-specific files (b_linux.go, //go:build darwin) or code that refers to runtime.GOOS is only accepted on the same OS and architecture.
  • A package with floating-point code is only accepted on the same architecture.

Rust (Cargo)

Needs a Cargo workspace or package with a committed Cargo.lock. The unit is a cargo test target of a workspace member.

Test idWhat cargo test runs
<package dir>#libthe library's unit tests
<package dir>#docthe library's doctests
<package dir>#bin:<name>a binary's unit tests
<package dir>#test:<name>an integration test file tests/<name>.rs
cd your-workspace
vci init --adapter cargo --key ~/.ssh/id_ed25519.pub
git add vci.toml .vci/allowed_signers .git-meta Cargo.lock && git commit -m "Enable vci"

vci run 'crates/b#test:b' --key ~/.ssh/id_ed25519   # one unit
vci run crates/b --key ~/.ssh/id_ed25519            # every unit of that package
vci plan --base-ref origin/main
vci push

A weaker guarantee than the other adapters. Rust has no hook for what a test reads at run time. Instead, every file in the package directory of the unit, and of every in-repo crate it builds, is an input. A test that reads files elsewhere in the repository must declare them:

[[inputs]]
match = ["crates/b#test:*"]
extra = ["testdata/**", "shared/config.json"]

vci scans the source for undeclared paths and refuses the unit when it finds one, but a path built at run time is not seen.

What is refused

Decided by scanning the source text: child processes (Command::new), sockets and network crates, FFI and libc, env::vars(), a unit where no test ran, and env mode "loose". The cargo adapter only attests in strict mode.

Laptop to Linux runner

  • rustc and cargo must be identical, including the LLVM version. Use rustup with rust-toolchain.toml on both sides. Homebrew's rustc can report a different LLVM and then never matches.
  • Every target-dependent cfg in the unit's code must evaluate the same on both platforms. cfg(unix) is fine between macOS and Linux; cfg(target_os = "linux") makes the unit run.
  • Code using std::env::consts::OS or platform math functions pins the unit to the attesting OS and architecture.

Rails

Needs Rails 8 with Minitest and the project's Ruby with its bundle installed (tested with Ruby 3.4.9, SQLite). The unit is a Minitest test file, one of those bin/rails test runs by default. RSpec is not supported yet.

cd your-app
bundle lock --add-platform x86_64-linux   # so the CI runner can install the same bundle
vci init --adapter rails --key ~/.ssh/id_ed25519.pub
git add vci.toml .vci/allowed_signers .git-meta Gemfile.lock && git commit -m "Enable vci"

TZ=UTC vci run test/models/b_test.rb --key ~/.ssh/id_ed25519
TZ=UTC vci plan --base-ref origin/main
vci push

The collector is plain Ruby loaded through RUBYOPT; nothing is installed into your project. It makes every run start from the same state:

  • a fresh database: each SQLite database of the test environment is redirected to a new temp file with the schema loaded. db/test.sqlite3 is never used;
  • one process: PARALLEL_WORKERS=1, no Spring, no Bootsnap caches;
  • a fixed Minitest seed (--seed 0).

What is recorded

Every Ruby file loaded, Zeitwerk's directory listings, every file read or checked (fixtures, templates, config, the schema), the gems used by version, and every variable read through ENV. Any change to Gemfile.lock runs everything.

What is refused

Child processes and forks, sockets, a database server (unless waived), writes inside the repository outside log/, tmp/, storage/ and coverage/, enumerating ENV, any failure, error or skip, and a test that made no assertion.

Database servers. PostgreSQL and MySQL test databases are refused by default. rails_allow_db = true under [policy] waives that: vci then purges each database and loads the schema before every file. With the waiver you state that the test database holds nothing but what vci loads.

Getting skips on a Linux runner

A generated Rails app needs a few changes before anything is skipped across machines:

  • Credentials. Active Record reads config/master.key at boot. That file is git-ignored, so CI never matches. Give the test environment its own committed credentials (bin/rails credentials:edit --environment test), remove the credentials, or declare RAILS_MASTER_KEY.
  • CI. Change the generator's config.eager_load = ENV["CI"].present? to config.eager_load = false in config/environments/test.rb.
  • Time zone data. Use gem "tzinfo-data" for every platform, and declare and set TZ=UTC.
  • Lockfile platforms. Gemfile.lock must list both arm64-darwin and x86_64-linux.
  • Keep vendor/.keep committed, and pin the exact Ruby in .ruby-version.
